狀態：**最高優先級專案治理規範（待專案負責人審閱並合併至正式規格）**
記錄日期：2026-10-26（臺灣時間）
適用範圍：iKey 所有分支、ESP32、Render、Google Apps Script / Sheets、GitHub、LINE 與任何第三方資源。

## 最高規格：先確認授權與額度，再動作

1. **不得自行新增雲端資源**：新建 Render Web Service、資料庫、付費方案、外部帳號或其他可能占用免費額度的資源，須先明確說明成本／額度影響、替代方案及可能的自動部署，並取得使用者對**具體操作**的明確授權。授權檢查現有設定不等於授權建立新服務。
2. **預設只讀**：在使用者沒有逐項同意之前，只能查詢與提出建議；不得自行部署、合併 PR、修改 main、改動正式 Render 或正式資料庫。
3. **免費額度為硬限制**：新增資源前先查核當前方案限制及既有資源用量；若無法確定，停止並請使用者確認，不得猜測。
4. **優先零新增服務**：ESP32 整合應優先以現有正式 Render 的安全測試機制、離線／本地模擬、GitHub 測試分支及非部署測試進行；如涉及正式站改動，仍需明確核准。
5. **機密保護**：裝置密碼、API Token、資料庫金鑰不得貼在聊天、commit 或公開日誌。測試裝置 ID 不等於授權憑證。
6. **部署閘門**：提出變更 → 查核影響與成本 → 使用者明確同意 → 執行 → 實際驗證 → 回報 SHA、環境、結果、回滾方式。
7. **事故處理**：一旦使用者指出超出授權，立即停止相關操作，優先回復／刪除意外資源，實際查核完成狀態，並在交接文件保留完整事件與改進措施。
8. **規範優先順序**：本規範對 iKey 專案的部署／資源操作優先於一般開發便利性建議；不得以過去概括授權推定已獲得新增資源的同意。
