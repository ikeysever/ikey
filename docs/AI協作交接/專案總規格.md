# iKey v3.1｜現行架構與公告整合規格

## 產品定位
iKey v3.1 採多專案、多 iBOX 管理；主線一負責網站前端，包括登入與帳號、專案管理、裝置狀態、開鎖操作、公告與通知、動畫及跨裝置體驗。後端、GAS、韌體與實體設備分工獨立。

## 本次公告整合
- 前端：`public/announcements-admin.js`；介面：`public/super-admin.html`。
- Render 路由：`gen3-auth/announcement-router.js`。
- GAS 程式：`gen3-auth/Code.gs`，需核對線上部署版本。
- API：`/api/announcements` 與 `/api/admin/announcements`；管理端需 Gen3 session 與 super_admin。
- 正式資料表：`System_Announcements`、`System_Announcement_Reads`。
- 原始 API 文件：`docs/SYSTEM_ANNOUNCEMENTS_API.md`；其中 staging-only 限制為先前規劃，**已因 2026-11-07 使用者明確授權使用既有正式資料庫而需要重新審核**，不能直接照舊執行初始化或部署。

## 實際驗證狀態（2026-11-07）
- 已確認既有 Google Sheet `iKey_Database`，並新增上述兩張空白工作表及標題列。
- 尚未證實線上 GAS 已部署公告 dispatcher、Render 已使用新版路由、網站 CRUD 已成功寫入資料庫。
- GitHub 的 GAS 原始碼與線上 Apps Script 並不自動同步。
- 禁止把資料表建立視為整條 API 已驗收。

## 保護界線
- 不修改 `main` 或正式 Render 部署，除非再次明確授權。
- 使用正式資料庫的授權**不等於**授權清除其他資料表、覆寫 GAS 或繞過權限驗證。
- 保留 super_admin 驗證、Session、同源檢查、資料表白名單與寫入確認。
