# iKey 3.1 — 專案頁載入效能分層（2026-10-26）

## 第一階段：本次實作

- 新增 `public/project-display-cache.js`，使用單一分頁的 `sessionStorage`，有效期 45 秒，只保留專案展示欄位；不保留邀請碼、密碼、權限判定或設備即時狀態。
- `projects.js`：若有有效展示快照，先呈現專案清單，並同步向 `GET /api/projects` 重新驗證；伺服器資料成功後覆寫展示快照。錯誤時呈現舊資料提示，不允許其作為任何安全操作的依據。
- `project.js`：先顯示快照中的專案名稱，但實際專案內容仍等待正式 API 成功回應後才開啟。
- `project-devices.js`、`project-other-settings.js`：仍必須取得伺服器的 owner-scoped 專案資料才顯示管理區；不以快取作權限驗證。
- 登出時清除展示快照；建立專案成功後清除快照。保留 `cache:'no-store'` 的動態 API 驗證。

## 第二階段：待測量與評估

- 量測瀏覽器 API response time、Render 冷啟動、GAS 與 Sheets 往返耗時。
- 如需進一步減少跨頁 API 次數，評估以經驗證的登入身分為範圍建立 server-side 短期資料快取，並在寫入時失效。不可將權限、解鎖、即時心跳或密碼驗證改為讀取前端快取。
- 圖像、CSS、JS 可使用版本化資產快取；音效只預取清單，音檔按使用者選擇載入。
